# Тест-план: OAuth авторизация (Госуслуги + ВКонтакте)

**Дата:** 18.03.2026
**Статус:** ⏳ Требуется бэкенд-разработка

## 🔧 НЕОБХОДИМЫЕ УСЛОВИЯ (НЕ ВЫПОЛНЕНЫ)

### ВКонтакте

- [ ] Создать приложение https://vk.com/apps
- [ ] Получить Client ID
- [ ] Настроить redirect URI: `https://voevoda.ru/auth/vk/callback`
- [ ] Добавить переменные в `.env`: VK_CLIENT_ID=**_, VK_CLIENT_SECRET=_**

### Госуслуги (ЕСИА)

- [ ] Регистрация организации в ЕСИА
- [ ] Получение сертификатов
- [ ] Настройка тестового контура
- [ ] Добавить переменные: ESIA_CLIENT_ID=**_, ESIA_CERT_PATH=_**

## 📋 ТЕСТ-КЕЙСЫ

### ВКонтакте — Позитивные сценарии

**VK-01:** Вход через ВК (существующий пользователь) — Нажать "Войти через ВКонтакте", подтвердить доступ → Пользователь авторизован, редирект на главную
**VK-02:** Вход через ВК (новый пользователь) — Нажать "Войти через ВКонтакте", подтвердить доступ → Создаётся новый профиль, пользователь авторизован
**VK-03:** Привязка ВК к существующему аккаунту — Войти по логину/паролю, зайти в настройки, нажать "Привязать ВК", подтвердить → Аккаунт привязан

### ВКонтакте — Негативные сценарии

**VK-04:** Отказ в доступе — Нажать "Войти через ВКонтакте", нажать "Отмена" → Возврат на страницу входа, сообщение "Вход отменён"
**VK-05:** Ошибка приложения — Ввести неверный Client ID → Ошибка "Приложение не найдено"
**VK-06:** Неверный redirect URI — Настроить неверный URI → Ошибка валидации

### Госуслуги (ЕСИА) — Позитивные сценарии

**ES-01:** Вход через Госуслуги (успех) — Нажать "Войти через Госуслуги", ввести тестовые данные ЕСИА → Пользователь авторизован
**ES-02:** Первый вход через Госуслуги — Нажать "Войти через Госуслуги", ввести данные → Создаётся новый профиль

### Госуслуги — Негативные сценарии

**ES-03:** Отмена на портале — Нажать "Войти через Госуслуги", отменить действие → Возврат на страницу входа
**ES-04:** Неверный пароль ЕСИА — Ввести неверные данные → Ошибка авторизации
**ES-05:** Истекший сертификат — Использовать просроченный сертификат → Ошибка соединения

## 📌 ЗАКЛЮЧЕНИЕ

Функционал OAuth требует реализации на бэкенде. Пункт будет выполнен после развёртывания Django-бэкенда и регистрации приложений. На данный момент создан тест-план для будущего тестирования.
